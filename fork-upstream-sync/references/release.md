# 发布来源、版本与 tag

检查时需要报告候选版本，或准备发布时读取。检查模式只计算并报告版本，不创建分支、tag 或执行 push。发布前固定上游 SHA 和有效定制，使用当前候选的验证结果。来源选择与检查、同步、push、PR 和发布授权相互独立。

## 分支快照

默认采用已确定的上游同步分支快照，优先沿用项目已确认的发布线和版本参照规则。没有规则时：

1. 将可选 `v` 前缀之后符合 `X.Y.Z` 的 tag 视为稳定版本，按 SemVer 的整数元组比较。包名前缀或其他版本体系按项目规则过滤，预发布及无关包 tag 只报告。
2. 带注释 tag 解析到 commit，使用可达性检查筛选 `upstream-commit` 历史里的版本。例如 `git merge-base --is-ancestor <tag-commit> <upstream-commit>`。
3. 在可达且属于目标发布单元的稳定 tag 中选择**版本最高者**。`git rev-list --count <tag-commit>..<upstream-commit>` 只报告距离，不决定版本高低。同版本多个 tag 指向不同提交时先核对来源，不任意选取。
4. 没有可用参照时报告缺失，不编造版本。候选包含固定上游 SHA 和有效定制，不为发布退回旧 tag。对比已有自有发布记录，发现参照倒退或上游移动既有 tag 时停止该来源发布并报告。

分别审查参照 tag 到 `upstream-commit`、`upstream-commit` 到自有候选的完整差异，并核对提交图。候选中固定 SHA 之外的上游变化需要解释，不能静默切换到新 HEAD。

## 严格基于正式 tag

用户明确指定正式 tag 模式时，使用指定 tag，未指定版本则选择目标发布单元的最新稳定 tag，并解析到实际 commit。

* 从上游 tag commit 创建或复用可追溯的自有发布分支。分支名沿用项目约定，未约定时可用 `release/fork-<版本>`，与日常同步分支分开。
* 从合并前自有基线识别有效补丁及依赖顺序。可独立应用的定制提交使用 `git cherry-pick -x`。混有上游变更或 merge 的提交，按已确认定制差异做最小移植，并在提交说明记录来源，避免盲目搬运全部 ahead 提交。
* 审查候选相对上游 tag 的完整 diff，每处差异应属于有效定制或必要打包适配。此模式不包含 tag 之后的上游代码。
* tag 缺少补丁所需 API 时，报告原因或准备适配候选，不自行升级基线、删除补丁或切换到快照。
* 验证后使用从未执行候选代码的独立发布克隆，按授权先将候选分支推到自有仓库，并核对远端 commit，再创建指向该 commit 的自有 tag。该克隆只接收固定的候选 Git 对象，不复制验证环境的配置、hooks、缓存或状态。没有候选分支 push 授权时，保留本地候选并说明缺少的操作范围。

## 自有 tag 命名

沿用目标项目已确认的命名约定。没有约定且使用 SemVer 时，自有标识默认为中性的 `fork`，可由调用参数或项目配置替换，不从账号或组织名推导。

| 来源 | 默认 tag 示例 |
| --- | --- |
| 正式 `v1.2.3` 或 `1.2.3` | `1.2.3-fork.1` |
| 以 `1.2.3` 为参照的上游 `master` 快照 | `1.2.3-fork.master.1` |
| 以 `1.2.3` 为参照的上游 `main` 快照 | `1.2.3-fork.main.1` |

* 分支字段使用实际上游分支名。分支含 `/` 等不能直接用于 SemVer 的字符时，采用已约定的版本标识映射，未约定则先确认，避免不同分支共用一个版本序列。
* 相同参照版本、自有标识、来源和上游分支下，有效代码或打包内容变化才递增末尾编号。新的版本参照使用新的前缀。只有 Skill 或维护说明变化不递增项目版本。
* 查询远端自有 tag 及来源记录。核对上游 SHA、定制与有效打包内容，同一来源内容已发布则不重复发版。重试复用同一版本，push 失败不增加编号。
* 这些后缀属于 SemVer 预发布标识，因此 `1.2.3-fork.main.1` 的版本优先级低于正式 `1.2.3`，不表达提交时间。消费方应固定精确自有版本或等价的锁定提交，不用范围依赖自动选择这些 tag，也不依赖分支名字符串排序。
* 使用带注释 tag，指向已推送到自有仓库并验证的候选 commit。推送使用单个明确 tag refspec，不使用 `--tags`、force 或删除重建既有 tag。发布后解析远端 tag 并核对实际 commit。

## 来源注释

tag 注释记录本次真实数据：

```text
Upstream-Repository: 去除认证信息的上游仓库身份
Upstream-Source: branch 或 tag
Upstream-Branch: 实际上游分支名，仅 branch 来源填写
Upstream-Tag: 版本参照 tag
Upstream-Tag-Commit: 参照 tag 对应的完整 commit SHA
Upstream-Commit: 本次固定采用的完整上游 commit SHA
Fork-Commit: 完整候选 commit SHA
Customizations: 保留或调整的定制
Validation: 当前候选实际执行的检查与结果
```

快照模式以 `Upstream-Commit` 为代码基线，tag 只作版本参照。正式 tag 模式的两个上游 commit SHA 相同。旧自有 tag 缺少来源时通过提交图和内容核对，不移动旧 tag 或无证据推断基线。
