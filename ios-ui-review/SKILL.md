# iOS 界面审查

默认只读审查。用户明确要求修复时，按其授权范围修改代码。

## 选定场景

* 阅读目标项目的规则和相关设计。审查改动时查看完整 diff，确定受影响的入口、状态和预期行为。
* 检查正常态及与改动相关的边界态。布局改动优先检查小屏，涉及 iPad 共用页面或分栏时检查宽窄窗口。按风险补充深色模式、动态字体和较长本地化文案。
* 复用项目已有的 UI 测试、测试数据和截图工具。需要运行定向回归时使用项目既有流程，也可使用已安装的 `ui-regression-check`。需要补充证据时，可在测试环境通过模拟器操作界面。使用隔离测试数据，遵守项目的设备与账号约定。

## 获取并核对证据

如截图保存在 XCTest 结果包中，用本机 Xcode 导出附件：

```bash
xcrun xcresulttool export attachments --path "$result_bundle" --output-path "$screenshots_dir"
```

将两个变量设为当前批次结果包和截图输出目录。根据 `manifest.json` 匹配测试和附件，逐张打开相关原图，确认页面、状态、方向和裁切。若旋转后截图方向或尺寸可疑，取模拟器整屏截图复核。历史截图可作对照，当次结果需有当次证据。

* **布局与视觉**：看对齐、间距、层级、背景衔接和对比度。检查长内容是否遮挡关键操作，文字放大后是否还能阅读与操作。
* **状态与反馈**：按改动检查正常、空态、错误、禁用或成功反馈。对照选择、清除、取消和返回前后的画面，确认显示与预期状态一致。
* **操作与焦点**：通过实际点击、滚动和键盘切换检查误触、焦点，以及用户能否找到并触发关键操作。用操作结果或测试断言验证状态，用录屏记录转场问题。视觉结论以查看截图或画面为依据。

## 报告

逐项写明问题、影响、设备或窗口、复现步骤及截图或录屏位置。根据预期行为区分产品缺陷、设计建议、测试问题和环境限制。说明已检查的状态、未验证项和相关测试结果。真实运行产物留在目标项目的验证环境。
